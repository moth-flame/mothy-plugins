# PRD Template (operational copy)

Source of truth: https://docs.google.com/document/d/1WUkbssjpLzkxIsTZ0VAca1FagCZ4maTKTeEaqOMiPP4/edit
Synced: 2026-08-29 (wave 2). If this copy and the Google Doc disagree, the Doc wins — re-sync this file.

Section order (exact):

1. **Title + header**: Status [Draft/Final]; Drafted with [prd skill vX] — Human review
   status; Related documents: Registry entry · Idea Dossier · Prototype · PR/FAQ · (legacy 1-Pager only for
   older projects — the 1-Pager is retired).
2. **Change History**: one line per change (Name — description — date); first row credits
   the human author.
3. **Objectives**: 1-2 sentences, the value-oriented outcome, not a functional description.
4. **Problem Statement and Value Hypothesis**: opportunity headline ("Because of
   [change/shift], we should [approach] by [timeline]...") + quantified pain (frequency ×
   reach × cost + what-happens-if-unaddressed) + the five-slot template — all three in
   problem-statement.md. Starts from intake dossier + prototype evidence + PR/FAQ.
5. **Prototype & Evidence**: prototype + demo links; validated; invalidated/changed; what
   the prototype gets away with that production cannot; "prototype is not the codebase"
   statement. Author attestation (human-only): real customer conversations; riskiest
   assumption in the author's own words.
6. **Persona(s)**: one line each — role name + what they want. Job stories live in
   Milestones.
7. **Success Metrics**: metric — value of metric — target framed before → after (current
   measure → target by date) — how INSTRUMENTED. At least one metric, the North Star,
   must measure itself with zero human intervention: state what the product emits (event,
   counter, query) and where the number lands. Bespoke instrumentation beats adopting an
   analytics suite. AI features: user metrics AND AI-quality metrics.
8. **Scenario(s)**: a prototype walkthrough (link + video) per persona satisfies this;
   narrative 3-act scenarios only for what the prototype doesn't cover.
9. **Milestones** (maturity ladder: Alpha internal → Beta ≥1 external customer → GA):
   per milestone — Related Job Stories with MoSCoW in the exact format "(Must) As a
   [persona], while [situation/location], I want to [action] so that [job-to-be-done]";
   Other scope with MoSCoW; relative Fibonacci complexity per story/item. Must = required
   to ship that milestone. These job stories are the requirements contract for the
   agent-orchestrated build (/mothy:plan → /mothy:build → /mothy:test) — no sprints, no
   user-story tickets.
10. **Timeline and Complexity**: optional calendar checkpoints (test-by / launch-by,
    human-decided — agent-orchestrated work happens in hours and days); the complexity map
    in relative Fibonacci points, items sized against each other within THIS project only
    (no time units, no cross-project normalization), human-confirmed.
11. **Features Out**: explicitly not building, and why. Never empty.
12. **Biggest Assumptions**: ledger — [Assumption] — Status: Validated/Testing/Assumed —
    Validation owner.
13. **AI Behavior & Evaluation** (only when AI-powered; see ai-feature-addendum.md):
    model/approach; input spec + output quality criteria; eval set (contents, thresholds,
    CI, gates Beta→GA); dual success metrics; failure-mode handling; post-GA drift
    monitoring cadence + owner.
14. **Messaging**: link the PR/FAQ (required for visioning); versioning copy for existing
    customers / prospects / partners.
15. **Design**: Prototype Link & Production Deltas (auth, data handling, error behavior,
    performance, accessibility, scale); **Workflow Diagrams** (generated by the prd skill —
    Mermaid flow/sequence diagrams of the future-state flows, rendered and inserted into
    the doc); **Design Artifacts** (Figma or other design links when they exist; otherwise
    skill-generated first-pass artifacts marked as drafts); then System Architecture, Data
    Model, Interface/API Definitions, Functionality, Migration Strategy, Impact — fill what
    the current milestone requires (lean is legitimate at Alpha; GA requires all that
    apply).
16. **Security, Privacy, and Other Risks**: mandatory for government-facing work — data
    handling, ATO/impact-level implications, named security sign-off. "Unknown + owner"
    beats reassurance.
17. **Alternatives**: solutions considered and rejected, with reasons.
18. **Open Questions/Issues**: Question — Answer — Answered by.
19. **FAQ**: the hard questions (persona/segment; why now; what might disappoint;
    integration; most contentious; security posture in plain terms; imported PR/FAQ
    questions). No minimum count; no filler.
20. **Review Checklist** (roles): Author/idea sponsor; Peer PM; VP of Technology; Head of
    Product; Security reviewer (gov-facing).
