# Problem Statement & Value Hypothesis — the spine

Two mad-libs work together: the business-case framing (why NOW, quantified) and the
five-slot value hypothesis (who, what, tradeoff, differentiator). AI pre-fills every slot
from research; the human reviews slot by slot.

## The opportunity headline (business-case framing)

**Because of [change/shift], we should [recommended approach] by [timeline]. After, we'll
avoid [negative outcomes] while unlocking [positive outcomes].**

The [change/shift] slot is the "why now" — something changed that made this pain emerging,
high-cost, and growing. If nothing changed, ask why this wasn't worth doing last year.

## Quantify the pain (pick the format that fits)

- **Every [frequency], at least [reach] are affected by [problem], costing [cost]. If not
  addressed by [timing], [it gets worse].**
- **Despite trying [failed solution], [who] still can't [desired outcome] because
  [problem], which has cost [cost of problem].**

Frequency × reach × cost turns a complaint into a business case; the failed-solution
variant preempts "why not just...". Research fills the numbers with sources; the human
vouches for them. Numbers you can't source get tagged Assumed in the assumption ledger.

## The five-slot value hypothesis

- **[Personas] experience [pain] when [job-to-be-done].**
- **This is because [problem(s)].**
- **[Pain] can be relieved by [solution].**
- **However, [persona] would have to be okay with [downside/limitation].**
- **Unlike [competitor/alternative/status quo], [solution] will [differentiating advantage],
  allowing Moth+Flame to [current goal].**

## Worked example (Hard Skills UX 2.0)

Learners experience confusion and difficulty with module navigation and control without
upfront onboarding. This is because there is too much customizability and few constraints —
navigation is "open-world," UI must be manually called up and placed, and diegetic controls
demand more precision than VR hand-tracking delivers. The confusion can be eliminated by a
guided path, Author-controlled UI placement, and simplified, protected hand interactions.
However, Learners would have to be okay with less freedom inside modules, and Authors would
have to be okay making UI placement and navigation choices throughout every module. Unlike
the open-world structure of recent modules, Hard Skills 2.0 favors the new Learner's
experience to eliminate onboarding, allowing M+F to grow its user base.

## Anti-patterns (reject the draft if present)

- **Empty downside**: "users would have to be okay with a new interface" — that's not a
  cost anyone feels. The downside is real when a named persona would genuinely grumble.
- **Strawman Unlike**: "unlike doing nothing" — name the actual alternative: a competitor,
  a manual workaround, the current feature.
- **Solution smuggled into the pain**: "[pain] is lacking [solution]" restated. The pain
  must stand on its own without mentioning the fix.
- **AI-invented pain**: every pain claim should trace to a customer conversation, intel, or
  the prototype's evidence loop — or be explicitly tagged as hypothesis in the assumption
  ledger.
