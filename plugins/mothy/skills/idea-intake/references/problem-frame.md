# The Problem Frame — one screen, plain language

Present this back to the submitter after Stage 2 research. Keep it to one screen.

## Format

**Idea name**: [2-4 words, the submitter's words]

**Who has the pain**: [persona in plain words — "instructors running AMC refresher courses,"
not "Persona 1"]

**The pain**: [one or two sentences, ideally in a customer's verbatim words from a
transcript, quoted and dated]

**The job they're trying to do**: [job-to-be-done]

**What we already know** (evidence found):
- [account/opportunity mentions from intel/OpsHub, with links]
- [meeting quotes from Granola, with dates]
- [prior write-ups found in Drive, with links — if a real one exists, route to
  process-navigator instead of duplicating]
- [market framing from web research, if any]

**Problem statement, first pass** (gaps marked [UNKNOWN]):
[Personas] experience [pain] when [job-to-be-done]. This is because [problem(s)]. [Pain]
can be relieved by [solution]. However, [persona] would have to be okay with
[downside/limitation]. Unlike [status quo], [solution] will [differentiator], allowing
Moth+Flame to [goal].

**Riskiest assumption**: [the thing that, if wrong, kills the idea — this is what the
prototype must test]

Close with: "Did I understand you right?" and iterate until the submitter owns the frame.
