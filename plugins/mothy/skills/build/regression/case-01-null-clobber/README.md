# case-01 — null-clobber-on-write

A PATCH route reads `manualLat` from the request body and writes it straight to Airtable's `Resolved Lat` column. When the AE clears the manual override (PATCH body contains `manualLat: null`), the route writes `null` to `Resolved Lat`, **clobbering a previously valid signature-mined value** that the role-parse and signature tiers had populated. The bug ships green because the unit test only covers the happy path (AE sets lat/lon). The self-written test never exercises the "AE clears a manual that was sitting on top of a signature value" case — exactly the failure mode R-05 describes from the other direction. Without an adversarial verifier scanning for R-03 / R-07 against the diff + rubric, this impl looks correct to its author, the test passes, the PR goes green, and the bug surfaces only when a Sales rep notices a stakeholder pin jumped back to the middle of the ocean.

What the verifier catches: R-03 fires on the unconditional `fields["Resolved Lat"] = body.manualLat` line — null-overwrite without guard. R-07 fires for the same line under the precedence lens — Manual-tier null is allowed to override Signature-tier value with no tier rank check.
